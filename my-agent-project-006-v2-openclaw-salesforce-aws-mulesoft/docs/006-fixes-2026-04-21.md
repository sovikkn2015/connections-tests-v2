# Project 006 — Systematic Fixes (2026-04-21)

Response to run11 eval analysis: 57.3% pass rate (86/150), L1 at 40%, L2 at 30%.
Root-cause analysis identified three patterns. This changeset addresses all three
and provides reproducible tooling.

## Root Causes Fixed

### RC1: Agent wasn't reliably calling tools — now forced via strict prompt
- **Change:** Rewrote `fsi-research` agent instructions in `openclaw/openclaw.json`.
- **New rules:**
  - MUST call the relevant MCP tool for every factual question (price, filing, news, CRM). No answering from parametric knowledge.
  - Symbol mappings baked into the prompt: "S&P 500" -> `^GSPC`, "10-year Treasury" -> `^TNX`, "crude oil" -> `CL=F`.
  - MUST cite tool + timestamp on every factual answer.
  - Never expose MNPI fields; trust the salesforce-crm MCP's server-side redaction.

### RC2: MCP errors were fatal — now resilient with retry + fallback
- **Change:** Added retry logic to:
  - `openclaw/mcp-rest-bridge.mjs` and `agentcore/mcp-rest-bridge.mjs`: 3 attempts, exponential backoff (500ms / 1.5s / 3.5s), 15s per-attempt timeout. Retries on 429, 5xx, network errors. Does not retry 4xx.
  - `openclaw/skills/fsi-research/pipeline.py::_mcp_call`: 3 attempts, 1s/2s/4s backoff, same retry policy.
- **Change:** Added Yahoo Finance fallback for `get_price_history` when Finnhub fails or returns `no_data`.
- **Change:** New `get_52_week_range` MCP tool that goes straight to Yahoo meta (skips the fragile Finnhub candle endpoint).

### RC3: Agent used wrong ticker for indices/commodities — now aliased server-side
- **Change:** `aws/mcp-servers/market-data/app.py` now has a `SYMBOL_ALIASES` table with 60+ mappings and a `resolve_symbol()` function applied at the top of every tool handler.
- **Change:** Any symbol starting with `^`, ending in `=F`, `-USD`, or `=X` routes directly to Yahoo Finance (skips Finnhub entirely).
- **Tested:** `aws/mcp-servers/market-data/test_resolve_symbol.py` — 16 unit tests, all passing offline.

### Bonus A: Pipeline SOQL prefers salesforce-crm MCP (closes task 1.8 properly)
`_sf_soql()` in `pipeline.py` now tries the `salesforce-crm` MCP first (gets server-side MNPI redaction) and falls back to direct SF REST only if the MCP fails.

### Bonus B: SAM template wires FINNHUB_API_KEY
The market-data Lambda code was expecting `FINNHUB_API_KEY` but the SAM template only passed `ALPHA_VANTAGE_API_KEY`. Added `FinnhubApiKey` parameter and env var. Updated `samconfig.toml.example`.

## Reproducibility

Two new scripts make the full build reproducible.

### `scripts/deploy-all.sh` — one-command deploy
```bash
./scripts/deploy-all.sh                   # full reproducible deploy
./scripts/deploy-all.sh --skip-sf         # AWS only
./scripts/deploy-all.sh --skip-sam        # SF only
./scripts/deploy-all.sh --skip-agentcore  # everything except AgentCore
./scripts/deploy-all.sh --verify-only     # just run smoke tests
```

Steps (all idempotent):
1. Verify prereqs (`sf`, `aws`, `sam`, `docker`, `agentcore` CLIs; AWS + SF auth)
2. `sf project deploy start` + assign IR_Agent_Access permset
3. Run 4 idempotent seed scripts in order
4. `sam build` + `sam deploy` (4 MCP servers + API Gateway + DLQ)
5. Deploy Bedrock Guardrails CloudFormation stack
6. `scripts/aws/setup-secrets.sh` (auto-discovers values from CLI + SAM outputs)
7. `agentcore deploy` (picks up new openclaw.json + bridge)
8. Smoke test: 4 targeted queries via eval harness

### `scripts/verify-006.sh` — read-only health check
```bash
./scripts/verify-006.sh              # PASS/FAIL/WARN table
./scripts/verify-006.sh --json       # JSON for CI
./scripts/verify-006.sh --fail-fast  # exit on first FAIL
```

Probes:
- AWS auth + Bedrock model access
- Secrets Manager has all 7 required keys
- SAM stack + API Gateway URL
- Each of 4 MCP servers (info + tools/list)
- Salesforce seed data counts (IR_Company__c >= 30)
- AgentCore runtime (if `AGENTCORE_AGENT_ARN` env set)
