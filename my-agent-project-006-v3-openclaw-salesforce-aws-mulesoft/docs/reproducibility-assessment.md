## What Could Trip a New User

### 1. Bedrock model access approval delay (5-30 min)

Sonnet 4.5 and Haiku 4.5 require explicit model access grants in the AWS console. The preflight script checks this with a real 1-token probe, but a new user might not realize they need to request access first. The RUNBOOK documents this in Section 1.3.

**Mitigation:** Preflight catches it. RUNBOOK documents it. No code change needed.

### 2. Salesforce Developer Edition org setup

A new user needs a Salesforce Developer Edition org with FSC (Financial Services Cloud) features. The standard Developer Edition may not have all FSC objects. The RUNBOOK doesn't explicitly call out which SF edition is required.

**Mitigation:** The `sf project deploy start` will fail with clear errors if objects are missing. The user can then create the custom objects manually or use a different org.

### 3. MuleSoft Anypoint 30-day trial expiry

The Anypoint Platform free tier is a 30-day trial. After that, CloudHub deploys will fail. The RUNBOOK doesn't mention this.

**Mitigation:** Add a note to RUNBOOK Section 1.2.

### 4. NAT gateway quota

The CDK stack creates NAT gateways. AWS accounts have a default quota of 5 per region. If the user has other VPCs, they might hit the limit. The preflight script checks this.

**Mitigation:** Preflight catches it with exact remediation command.

### 5. `npm ci` requires `package-lock.json`

The frontend build uses `npm ci` which requires `package-lock.json` to be committed. If it's missing, the build fails.

**Mitigation:** `package-lock.json` is committed to the repo.
