## 0. Why This Module

ICE Data Services (and a broader family of gRPC-native market-data vendors incl.
certain Nasdaq Pro feeds and Refinitiv Real-Time-Distribution endpoints) publishes
its NBBO-snapshot and trade-tape APIs over gRPC with mTLS + bearer-token auth.
HTTP/REST adapters cannot speak gRPC, so Steering Rule 10 calls for a separate
Python adapter using `grpcio.aio`.

This spec ships the ICE Data reference implementation. Additional gRPC vendors
(Refinitiv RTDS, Nasdaq Basic NLS) reuse the same `GrpcVendorClient` pattern and
deploy as sibling sub-chart packages.

## 3. Architecture

```
         ┌─────────────────────────────┐
         │  M6 MCP Gateway             │
         └──────────────┬──────────────┘
                        │ mTLS
                        ▼
   ┌───────────────────────────────────────────────┐
   │  m11-grpc-adapter pod (Python 3.12)            │
   │   FastAPI MCP server                           │
   │   ├─ GET /                                     │
   │   ├─ POST /tools/list                          │
   │   └─ POST /tools/call                          │
   │        │                                       │
   │        ▼                                       │
   │   IceDataClient                                │
   │    • grpc.aio.secure_channel (1 per tenant)    │
   │    • mTLS client cert + bearer metadata        │
   │    • CircuitBreaker + RateLimiter              │
   │    • AuditEmitter → stdout                     │
   │        │                                       │
   │        ▼                                       │
   │   IceVendorStubProtocol (ABC)                  │
   │    • RealIceStub (generated from .proto)       │
   │    • FakeIceStub (deterministic fixtures)      │
   └───────────────────────────────────────────────┘
```

The `.proto` file is committed at `src/m11_grpc_adapters/ice_data/proto/ice_data.proto`.
Generated stubs live under `src/.../ice_data/generated/` and are regenerated by
`scripts/gen_ice_stubs.sh` only when the proto changes. The fake stub is hand-written
in `client/fake_stub.py` and shares the Protocol so swapping is free.

The gRPC channel is created per-tenant (tenant_id is bound into the channel
credentials so BGP / ACL segmentation at the vendor side is respected). Channels
are cached in `IceChannelPool` keyed by `tenant_id`, with a max pool size from
env. Idle channels are closed after `ICE_CHANNEL_IDLE_S` seconds.

## 4. MCP Tool Surface

### 4.1 `ice.market_data_snapshot`

Current NBBO snapshot for N securities.

```python
class MarketDataSnapshotInput(BaseModel):
    model_config = ConfigDict(extra="forbid")
    securities: list[IceSecurityRef] = Field(min_length=1, max_length=100)
    include_depth: bool = False     # Level 2 book (entitlement-gated)
```

### 4.2 `ice.trade_tape`

Historical trade ticks within a time window.

```python
class TradeTapeInput(BaseModel):
    model_config = ConfigDict(extra="forbid")
    security: IceSecurityRef
    start_time: datetime           # UTC, ISO 8601
    end_time: datetime
    max_ticks: int = Field(default=10_000, ge=1, le=100_000)

    @model_validator(mode="after")
    def _check_window(self) -> Self:
        if self.end_time <= self.start_time:
            raise ValueError("end_time must be > start_time")
        if (self.end_time - self.start_time).total_seconds() > 30 * 86_400:
            raise ValueError("window exceeds 30-day ICE retention ceiling")
        return self
```

### 4.3 `ice.reference_data`

Security master — symbol lookup, asset class, tick size, lot size, trading hours.

```python
class IceReferenceDataInput(BaseModel):
    model_config = ConfigDict(extra="forbid")
    securities: list[IceSecurityRef] = Field(min_length=1, max_length=500)
    as_of_date: date | None = None   # None = latest
```

## 5. Security

### 5.1 Auth

- **mTLS**: client cert + key loaded from Vault paths `ICE_MTLS_CERT_VAULT_PATH`,
  `ICE_MTLS_KEY_VAULT_PATH`, `ICE_MTLS_CA_VAULT_PATH`. Supplied to gRPC via
  `grpc.ssl_channel_credentials()`.
- **Bearer token**: per-tenant, loaded from Vault path
  `ICE_BEARER_TOKEN_VAULT_PATH`. Supplied via
  `grpc.metadata_call_credentials(lambda ctx, cb: cb([("authorization", f"Bearer {tok}")], None))`.
- **Channel credentials** = `grpc.composite_channel_credentials(ssl, bearer)`.

### 5.2 Channel Pool

```python
channel = grpc.aio.secure_channel(
    target=cfg.ice_target,
    credentials=composite,
    options=(
        ("grpc.keepalive_time_ms", 30_000),
        ("grpc.keepalive_timeout_ms", 10_000),
        ("grpc.keepalive_permit_without_calls", 1),
        ("grpc.http2.max_pings_without_data", 0),
        ("grpc.max_send_message_length", 16 * 1024 * 1024),
        ("grpc.max_receive_message_length", 64 * 1024 * 1024),
    ),
)
```

Keepalives prevent idle-reap by vendor load balancers. Max message sizes are
generous for trade-tape responses but bounded to prevent unbounded memory.

### 5.3 Fail-Closed

If channel creation throws `grpc.aio.AioRpcError.UNAUTHENTICATED` or
`UNAVAILABLE` on every retry in the breaker window, the tool returns
`vendor_unavailable` with `retryable=true`. No stale-cache fallback — the
adapter never fabricates market data.

### 5.4 Circuit Breaker + Retry

Same pattern as M11 REST. Retry policy: 2 retries on `UNAVAILABLE` or
`DEADLINE_EXCEEDED`, exponential backoff `200ms * 2^n` with jitter.

### 5.5 Per-Call Audit

Every tool call emits `ice.tool_audit` to stdout. Failure events include the
gRPC status code (string form, e.g. `UNAVAILABLE`, `RESOURCE_EXHAUSTED`) plus
the adapter error code.

## 6. Canonical Error Mapping

| gRPC status | Adapter error code | Retryable | HTTP equivalent |
|-------------|--------------------|-----------|-----------------|
| `UNAUTHENTICATED` | `vendor_auth_failed` | No | 401 |
| `PERMISSION_DENIED` | `vendor_not_entitled` | No | 403 |
| `INVALID_ARGUMENT` | `vendor_bad_request` | No | 400 |
| `NOT_FOUND` | `vendor_not_found` | No | 404 |
| `DEADLINE_EXCEEDED` | `vendor_timeout` | Yes | 504 |
| `RESOURCE_EXHAUSTED` | `vendor_rate_limited` | Yes (backoff) | 429 |
| `UNAVAILABLE` | `vendor_unavailable` | Yes | 503 |
| channel closed mid-call | `vendor_transport_error` | Yes | 502 |
| `UNKNOWN` / other | `vendor_error` | No | 502 |

## 8. Testing Strategy

### 8.1 Unit (≥ 20)

- Happy path × 3 tools
- gRPC status translation × 9 codes (happy + each in §6)
- Channel reuse across 100 calls (no leaks — `channel.get_state()` observed)
- Per-tenant channel isolation (tenant A's credentials never reach tenant B)
- Retry-on-UNAVAILABLE attempts counted × 3 (1st, 2nd, giveup)
- Breaker OPEN → short-circuits without channel touch
- pydantic validators × 3 (window ceiling, max securities, identifier format)
- Audit success + failure × 3 tools
- Bearer token refresh trigger
- Cert-file reload on secret rotation
- Shutdown closes all channels + cancels in-flight calls

Target: **25 unit tests**.

### 8.2 Integration (≥ 5)

- Local gRPC server (aio) serves the .proto responses → 3 happy-path round trips.
- `POST /tools/call` end-to-end via FastAPI TestClient.
- Channel-reuse stress (50 sequential calls → 1 channel observed).
- Concurrent multi-tenant (tenant A + tenant B → separate channels).
- Graceful shutdown under in-flight calls (no deadlock, pending calls cancelled).

### 8.3 No Live Vendor

Deterministic tests only. Real ICE creds gate is an ops concern.
